# Celestials Game Hub

Multiplayer party & board game hub over LAN/Internet. Players create a **room** first and the host **selects a game** afterward; once a match ends, the room can switch games without anyone rejoining. Each game is a plugin in `games/<dir>/`.

## Project Principles
- **Zero dependencies**: pure Node.js (>=22.13, using built-in `node:sqlite`), no `npm install`, no build step. Plain ES modules (`"type": "module"`), loaded directly by the browser.
- **Authoritative server**: the server owns all game state. Clients only send intents (`action`); the server validates rules and broadcasts state + events to everyone.
- **Vietnamese UI & comments**: user-facing strings and in-code comments are written in Vietnamese (while repository documentation is standardized in English).
- **Pure game logic**: game rules must be pure functions (no I/O, no `Date.now()` — use the `now` parameter) so matches can be simulated and tested deterministically with `tools/simulate.js`.

## Running & Testing
```bash
node server.js                         # http://localhost:3000
node server.js --online                # + Cloudflare tunnel (npm run online), link printed to console & used by "Copy invite link"
HUB_DEV=1 PORT=3917 node server.js     # also expose "_..." games (e.g. _template)
node tools/simulate.js <gameId> [n] [key=value...]   # n all-bot matches: catch errors/softlocks, estimate duration; players=<k> = k bots in random seats
node tools/smoke.js <gameId> [port] [seconds]        # E2E over WebSocket against a running server (Node 22+)
node tools/load.js <gameId> [rooms] [players/room] [seconds] [port]  # load test: many bot-filled rooms, prints bandwidth + /api/health
HUB_WORKERS=1 node server.js           # single process (default = CPU core count; see "Multi-process")
```
Before considering a game finished: `simulate` must have zero errors/softlocks, `smoke` must pass, and you should playtest it in a browser (via `playwright-cli`). Note: each `playwright-cli` command takes ~2s, which is too slow for real-time games — for real-time games, inject an automation script via `eval` or `run-code`.

## Adding a New Game (Checklist)
1. `cp -r games/_template games/<gamename>` (directory names without a leading `_` appear in the standard hub).
2. `manifest.js`: set `id` (unique), `name`, `icon`, `tagline`, `description`, `minPlayers`, `maxPlayers`, `seats` (`maxPlayers` entries of `{name, color, label?}`), `options`, `order`, `tags` (genre filter chips + search in "Change game"; reuse existing tags like `Bài`, `Cờ`, `Phản xạ`), `turnMs` (turn-based games). Optional: `seatOn(i, opts)` → `false` closes seat `i` for that option (hub automatically closes/reopens seats; e.g. 2-team Codenames closes the Green block). `shuffle: false` disables seat shuffling on match start (when seat index carries rule meaning, e.g. Codenames teams + Spymasters) — see "Random Seat Shuffling" in Notes.
3. `server.js`: implement the game rules per the interface below. Turn-based games: omit `tickRate/tick`, implement `turn/bot/animDuration`. Implement `result` so the leaderboard knows full table placements, not just the winner.
4. `client.js` + `style.css`: UI. Scope every CSS selector under a unique game root class (e.g. `.ccn`, `.px`). The hub uses the light **"Botanical Sage & Warm Cream" (*Xanh lá dịu & Kem ấm*)** theme: reuse variables from `public/hub.css` (`--surface`, `--chip`, `--line`, `--ink`, `--muted`, `--primary`, `--accent`, `--danger`, `--felt`, `--wood`, `--shadow`) instead of hardcoding colors; avoid neon glows/gradients. Render colored player names with `<b class="pn" style="--c:color">` (auto-darkens on light surfaces); tag dark regions (felt tables, boards) with class `dark` to keep original colors.
5. Run `node tools/simulate.js <id> 50`, `node tools/smoke.js <id> <port>`, and playtest in a browser (including mobile viewport).
6. Update the games table in `README.md`.

## Game Server Interface (`games/<dir>/server.js`, `export default {...}`)
| Method | Required | Description |
|---|---|---|
| `create({ seats, opts, now })` → `{ state, events }` | ✔ | `seats[i]` = `{ kind: 'human'\|'bot', name }` or `null` (open/closed seat). `opts` = chosen values matching `manifest.options`. |
| `act(state, seat, action, now)` → `{ ok, err?, events? }` | ✔ | Validates & applies `seat`'s action (mutating `state` in place). `ok:false` + `err` (Vietnamese) shows a toast to the player. Optional `quiet: true` skips immediate broadcast (for high-frequency input like movement; next `tick` batches it). Optional `say: [{p, text, to?, tag?}]` posts chat messages from seat `p` (typically bots). |
| `isOver(state)` → bool | ✔ | When `true`, the hub stops timers/ticks and records the match. |
| `result(state)` → `[{ p, s? }]` | recommended | Final placements for the leaderboard: all occupied seats ordered **best first**; adjacent entries with equal JSON `s` tie, entries without `s` are strictly ordered. If omitted, hub falls back to `state.winners`/`state.winner` (winner = 1st, others tied 2nd). Verified by `tools/simulate.js`. |
| `turn(state)` → `{ seat, auto?, autoDelay? }` \| `null` | turn-based | Active decision-making seat. `auto`: action automatically executed by the hub after `autoDelay` ms (e.g. single legal move) — takes priority over bots, so it also enables **reaction windows**: return `{ seat, auto: {type:'resolve'}, autoDelay: 3000 }` and allow any seat to `act` during the wait (see `games/meono`). Hub invokes `bot` for bot seats and `bot(..., {timeout:true})` on timeout (`manifest.turnMs`, or 3s if disconnected). Optional `ms` overrides `turnMs` for this decision (works with `{ seats, key }` too). |
| `turn(state)` → `{ seats: [...], key, ms? }` | simultaneous | Replaces `{ seat }`: all seats in `seats` (those not yet locked in) decide in parallel under a single deadline (`turnMs` or `ms`). Changing `key` starts a new phase/deadline. Hub calls `bot()` for bots (staggered 0.3–1.7s) and offline humans after 3s; on timeout, calls `bot(..., {timeout:true})` for remaining seats, setting `meta.auto` to an **array** of seats. See `games/incagold`. |
| `bot(state, seat, { timeout })` → action | turn-based | Bot AI; `timeout:true` = safe fallback move for a timed-out human (avoid wasting precious resources). |
| `animDuration(events)` → ms | recommended | Duration of client animations; hub waits before running the next bot/timer step. |
| `tickRate` (ticks/sec) + `tick(state, now)` → `{ events?, changed? }` \| `null` | real-time | Called periodically by hub; non-null return broadcasts to everyone (supports `say` like `act`). Real-time bot AI runs inside `tick`. |
| `view(state, seat)` → state | optional | Redacts private info (hands, hidden roles). `seat = -1` is a spectator. Defaults to full `state`. |
| `viewEvents(events, seat, state)` → events | optional | Like `view`, but for emitted events. |
| `chatTo(state, seat, now)` → `undefined` \| string \| `{ to: [seats...], tag? }` | optional | Scopes in-match chat (`seat = -1` is spectator): `undefined` = whole room, string = block with that error message, `{to}` = visible only to those seats (`-1` = spectators) and sender, `tag` prefixes sender name (e.g. 👻). Resets when match ends or returns to lobby. |

`events` is a game-defined array of objects (e.g. `{ t: 'roll', p: 2, v: 6 }`) used by clients to play animations; `state` is always the state **after** those events. Everything in `state` and `events` must be JSON-serializable.

## Game Client Interface (`games/<dir>/client.js`, `export default { mount }`)
`mount(root, ctx)` (may be `async`) renders the UI into `root` and returns an instance:
- `update(msg, { backlog, hidden })` — **required**, may be `async`. `msg = { matchId, game, state, events, meta, deadlineIn, recvAt }`. Hub invokes `update` **sequentially** (awaiting each Promise), so `await`ing animations is safe. `backlog` = queued message count (speed up if large); `hidden` = tab is hidden (skip animations). `meta.auto = seat` when hub auto-acted on timeout. Current turn deadline = `recvAt + deadlineIn` (`0` = none). For real-time games, hub coalesces queued messages and passes the latest state with concatenated `events`.
- `onRoom(room)` — optional; called when room metadata changes (online/offline, etc.).
- `emoteAnchor(seat)` → `{x, y}` screen coordinates — optional; where emotes, chat bubbles, and 🔊 voice indicators float for that seat.
- `unmount()` — optional; clean up any listeners/intervals attached outside `root` (`window`, `document`).

Hub-provided `ctx`:
- `ctx.game` — catalog entry (`id, name, icon, seats, options, ...`). `ctx.game.seats[i]` holds the color/name/label of the **player sitting in seat `i` for this match** (hub handles seat shuffling so color follows the player from the lobby) — always read seat colors from here, never hardcode game constants.
- `ctx.me()` → `{ uid, seat, isHost }` (`seat = -1` if spectating). `ctx.room()` → current room (`code, seats, members, opts, turnMs, ...`).
- `ctx.send(action)` → Promise `{ ok, err }` (errors auto-toast). `ctx.restart()` new match (host), `ctx.backToLobby()`, `ctx.exit()`.
- `ctx.loadCss(url)` → Promise; CSS is automatically unloaded on unmount. Pass `new URL('./style.css', import.meta.url)`.
- `ctx.ui` — `$, el, esc, pick, toast, openModal, closeModal, pickModal, floatAt, burst, confetti, fireworks, spawn, PALETTE, emoteBar(el), toolbar(el, { help })`.
- `ctx.sfx` — `tone, noise, ac` + built-in sounds `pop, click, error, tick, chat, myTurn, card, gong, whoosh, tele, boom, win`.
- `ctx.voice.volumes({ uid: 0..1 } | null)` — per-player voice chat gain (e.g. proximity audio); automatically reset on game unmount.
- `ctx.skin.face(seat, cls?)` → HTML string for that seat's **avatar** (placed next to names or inside seat dots): default = `<span class="hub-avw">` wrapping `<img class="hub-av">` plus the equipped avatar frame / combo effect; `'fill'` = `<img class="hub-av fill">` followed by an `<i class="hub-fr">` frame overlay. Always returns the `img` (hidden if no avatar) so the hub can live-patch it if the player changes avatars mid-match. `cls = 'fill'` fills the parent container (parent needs `position: relative` + border-radius); default is a 1.5em circle with `var(--c)` border. Dead/ghost players typically keep 💀/👻 instead. `ctx.skin.avatar(seat)` → URL | null, `ctx.skin.img(seat)` → loaded `Image` for canvas drawing | null. Hidden-identity games (*Impostor*) only show avatars where true identity is known.
- `ctx.skin` — equipped shop cosmetics for `seat` (bots/guests = null): `look(seat)`, `cls(seat, 'back'|'dice'|'easel')` → `' lk-bk lk-<id>'` | `''`, `set(el, seat, slot)` updates an existing element's skin, `hat(seat)` → hat ID | null, `drawHat(c2d, id, width, topY, seconds)` draws hats on canvas, `name(seat, text, color?)` → `<b>` name HTML with the equipped name effect (falls back to `.pn` seat colour), `title(seat)` → equipped title chip HTML | `''`, `comboCls(seat)` / `comboBg(seat)` → combo-set class / background layer HTML. Dice require face class `lk-df` and pip class `pip`. Cosmetics must never obscure rule cues (e.g. Ludo's `.golden` dice overrides skin; *Impostor* reads hats by visual disguise `l`, not true seat).

Only one game is mounted at a time, so module-level variables are fine — just reset them in `mount`. Elements `#modal`, `#toast`, `#fx`, `#chat`, `#voice-talk` belong to the hub (use via `ctx.ui`); do not duplicate those IDs. **Reserve the bottom-left corner (~70×115px) for the hub's voice 🎙️ + chat 💬 buttons** — do not place critical controls there. `emoteAnchor` is also used to position chat speech bubbles and 🔊 speaking indicators.

## WebSocket Protocol (`/ws`, JSON)
Connection: `/ws?room=<code>` routes straight to the worker owning that room (omitting `room` lands on any worker, fine for `hello`/auth/`create`). Joining a room on a different worker returns `{ ok:false, moved:true }`: the client reconnects with `?room=` and retries (`joinRoom`/`net.move` in `hub.js`, `smoke.js`).
Client → server: `{ id?, t, ...}` — if `id` is present, server replies `{ t:'res', id, ok, err?, ... }`. Per-connection messages are processed strictly in order.
- Outside room: `hello` → `{catalog, lan, pub, accounts}`, `register {name, pin}` / `login {name, pin}` → `{token, user}`, `auth {token}` → `{user}`, `logout {token}`, `create {name, game?}`, `join {code, name?, pid?}`, `leave`. Avatars (logged in): `avatar {data: dataURL | null}` → `{av}` (`null` deletes; ≤~88KB, JPEG/PNG/WebP, ≥2s cooldown). Shop (logged in): `shop` → `{wallet}`, `buy {item}` → `{wallet}`, `equip {slot, item|null}` → `{wallet}` (`slot: 'title'` equips achievement titles), `achievements` → `{ach: {unlocked: {id: at}, prog: {key: n}}, wallet}`, `rename {name}` → `{user, wallet}` (consumes one `u-rename` card); `wallet = {credits, earned, bonus, today, cap, owned, eq, bag: {cards, bought}}` (`bonus` = achievement coins, included in `earned`). Auth attaches to the socket and takes effect on subsequent `create`/`join` (client sends `auth` before `join` on reconnect).
- Inside room: `sit {seat}`, `unsit`, `seatKind {seat, kind:'open'|'bot'|'closed'}`*, `fillBots`*, `selectGame {game}`*, `opts {key, value}`*, `start`*, `lobby`*, `kick {uid}`*, `act {action}`, `emote {e}`, `chat {text}` (≤200 chars, ≥0.4s cooldown), `voice {on, muted?}` → `{vid}`, `rtc {to, tv, d}`. (*host only)

Server → client: `room {room}`, `game {matchId, game, state | ds, events, meta, deadlineIn}` (`ds` = delta from previous `game` message on this connection — `public/delta.js`; first match message, post-join/rejoin, and the following message always send full `state`; `hub.js` reconstructs `state` before calling `update`), `emote {uid, name, seat, e}`, `chat {msg: {id, uid, name, seat, color, text, at}}`, `chatLog {log}` (up to 50 recent messages on join/rejoin), `rtc {from, fv, d}`, `kicked {code}`, `credit {gain, win, wallet, delay}` (sent only to that account on recorded match end), `ach {unlocked: [ids], ach, wallet, delay}` (sent to each signed-in player after every non-aborted match, even with only 1 account), `fx {fx, seat, name, why: 'win'|'sit', delay}` (winner/sit-down cosmetic effect broadcast to the room).
- `room.home` (during matches with seat shuffling, otherwise `null`): `home[i]` = lobby seat index of the player occupying match seat `i` (color/name from `manifest.seats[home[i]]`).
- `room.seats[].av` / `room.members[].av` / `chat.msg.av` = avatar URL (`/avatar/<id>?v=<contentHash>`, immutable cache) or `null`.
- `room.seats[].look` / `room.members[].look` / `chat.msg.look` = equipped cosmetics `{frame?, name?, title?, bubble?, fx?, back?, dice?, hat?, easel?}` (IDs in `public/shop-data.js`) or `null`.
- `pid` is a secret reconnect token (stored in `sessionStorage` to reclaim seats after F5/disconnect); `uid` is the public ID shown in `room`. `acct` flags signed-in accounts.

## Architecture & Game Notes
- **In-RAM rooms**: restarting the server clears active rooms. Accounts and match history live in `data/` and persist across restarts.
- **Multi-process (`server.js`, `HUB_WORKERS`, default = CPU cores)**: primary listens on TCP, peeks the HTTP request header, and hands off sockets via `worker.send(msg, socket)` — `/ws?room=<code>` goes to `shardOf(code, N)`, other requests round-robin; workers emit `'connection'` and replay peeked bytes. Reused keep-alive proxy connections (Cloudflare/Azure) that upgrade on the wrong worker are forwarded back through primary (`fwd`). `create` generates room codes belonging to the handling worker. Shared state goes through `hub.db` (WAL, `busy_timeout`, `BEGIN IMMEDIATE` for purchases); avatar/cosmetic updates broadcast IPC `acct` so all workers invalidate caches and redraw rooms. Crashed workers auto-respawn (losing their in-RAM rooms). `HUB_DB_WAL=0` is used on network shares (Azure Files with `nobrl` in `deploy/containerapp.yaml`) in single-process mode.
- **Performance (`tools/load.js`, `GET /api/health`)**: the hot path is state broadcast — `broadcastGame` computes `view` once per seat (spectators share one), splits JSON to depth 2, and sends diffs (*Impostor* ~15–25%, *Draw & Guess* ~2% payload). Connections backing up >2MB are dropped (client auto-reconnects). Avoid slow calls in hot paths (`os.networkInterfaces()` on Windows takes tens of ms → `lanUrls` cached 60s); heavy queries (leaderboard) run in a worker thread.
- **Random seat shuffling (`shuffleSeats`/`unshuffle` in `hub/rooms.js`)**: for turn-based games (no `tickRate`, `manifest.shuffle !== false`), `startMatch` shuffles occupied human/bot seats (open/closed seats stay put) so table positions and turn order vary every match; game logic only sees match seat indices. Seat colors/names follow players via `match.home` → `seatInfo` and `room.home` → `ctx.game.seats`. `stopMatch` restores everyone to their chosen lobby seats. Real-time games (*Impostor*, *Draw & Guess*) and *Codenames* do not shuffle.
- **Host failover**: if the host is offline >15s, host transfers to another online member.
- **Accounts**: case-insensitive username + 4–8 digit PIN, 5 failed attempts lock for 60s; token stored in `localStorage.hub_token`, server stores hashes (max 10 devices/user). Signed-in users joining from another tab/device reuse their existing room member/seat. Renaming (✏️ next to the account name) requires a Rename Card and runs in one transaction (`accounts.rename` + `wallet.consumeCardRaw`); rooms pick up the new name immediately except mid-match (applied after the match).
- **Match history**: `startMatch` snapshots `match.players` (with accounts); on `isOver`, `record()` writes `{at, dur, room, game, opts, players: [{seat, acct, name, bot?, rank}]}` to `matches` + per-account rows in `mp` (only when ≥2 signed-in players finish). Returning to lobby mid-match (or abandoned room cleanup) records `aborted: true, by` (0 rating/credit impact).
- **Leaderboard (`hub/report-worker.js`)**: head-to-head match score per signed-in pair (+1 above, −1 below, 0 tie) divided by `(players − 1)` → `−1…+1`. Weight `weightOf(dur)` = `minutes / 10` rounded to 0.5, clamped to `×1…×3`. Rating `(−100…+100)` = `Σ(weight × score) / (Σ weight + PRIOR) × 100` with `PRIOR = 3`. Computed dynamically from stored `dur`. Players with `< MIN_GAMES (5)` rank at the bottom.
- **Credits & Shop (`hub/wallet.js`, `public/shop-data.js`)**: balance is derived via SQL from `mp` (`EARNED_SQL`: daily cap `min(dayCap, Σ raw)` minus `wallet.spent`). Formula: `CREDIT.base (15) × weightOf(dur)`, `×1.5` for 1st place (including ties), `dayCap = 300/day` (VN time). Achievement coins are added on top (`achBonus`, **outside** the daily cap). Cosmetics are intentionally vibrant (animated gradients/glows — an explicit exception to the soft theme, isolated in `shop.css` `.lk-<id>`) and never alter seat colors. Titles are **not sold** — they come only from achievements (IDs prefixed `ta-`; `COSMETIC(id)` = shop item or title). **Combo sets** (`COMBO`/`comboSet` in `shop.js`, deliberately unadvertised in the shop): equipping the avatar frame and name effect of the same theme (`fr-<x>` + `nx-<x>`, x ∈ sakura/ocean/gold/fire/rainbow/galaxy) adds an extra aura/particle layer (`.lk-cb-<x>`) wherever the avatar/seat is drawn. Consumables (`consumable: true`, slot `util`) stack in `wallet.bag.cards` and can be bought repeatedly; `firstSale` = % off the first purchase (`itemPrice`) — currently only the Rename Card `u-rename` (1000, first one 99% off). One-time migration `migrateShopV2` (`meta` key `shop_refund_v2`) refunded all spent credits and wiped previously bought items when the shop was rebalanced.
- **Achievements (`hub/achievements.js`, `public/achievements-data.js`)**: evaluated in `record()` for every **non-aborted** match with ≥1 signed-in human (independent of the ≥2-account rule for history/credits). General achievements (`gen-*`: games played/won, variety, streaks, 15-min marathon) apply to every game; game-specific ones need a `TRACKERS[gameId]` entry (`init()` → accumulator stored on `match.ach`, `onEvents(acc, events)` fed from `startMatch`/`afterAction`/`tick`, `eval({seat, rank, playersCount, opts, state, acc, bump, getProg})` → `{achId: bool}`) — currently only *Ludo* (`ccn-*`). Cumulative counters live in `ach_prog (acct, k, v)`; each achievement has `coins` and optionally a `title` (auto-equipped if none worn). When adding achievements for a new game: add the game to `ACH_GAMES`, entries to `ACHIEVEMENTS`, and a tracker keyed by the events your `server.js` emits.
- **Christmas theme (`public/xmas.css`, `public/xmas.js`)**: a light layer over the Botanical Sage theme under `html[data-theme="xmas"]` (default on; `#xm-toggle` in the corner of the home card; `localStorage.hub_xmas = '0'` turns it off). `xmas.js` builds one fixed `#xm` layer at `z-index: -1` (body background is made transparent so it sits behind every card): garland, snowy hills + pines + snowman, an occasional reindeer sleigh, ~30 snowflakes animated by CSS `transform` only (no JS loop, hidden under `prefers-reduced-motion`). Plus small card touches (candy-cane top border, holly sprig, tri-colour title bar). In a match (`show()` in `hub.js` sets `html[data-screen]`) the layer keeps only the garland + half the snow, visible in the empty space around the table, and the theme overrides `--felt` with a pine felt + faint snowflake pattern — so every game that uses `background: var(--felt)` turns festive with no per-game CSS (keep using `--felt`/`--wood` for tables in new games; leave the game root background transparent). Seat colours, `--primary`/`--cta`/`--accent` and game layouts are untouched; *Impostor* (opaque full-screen) hides the layer.
- **Avatars (`hub/avatars.js`, `public/avatar.js`)**: client crops to 192px square and compresses to WebP/JPEG before WebSocket upload; server validates magic bytes (no SVG) + size and serves with `nosniff` + CSP. Mid-match updates live-patch `#game-root img.hub-av[data-av]` (`patchAvatars`).
- **Kicks**: host-only, cannot self-kick, cannot kick mid-match; 2-minute rejoin ban per room (by account ID, or name for guests).
- **Chat**: 50-message in-RAM room history; keystrokes in chat input call `stopPropagation` so game hotkeys don't trigger; `Enter` opens chat, `Esc` closes.
- **Voice chat (`public/voice.js`)**: mesh WebRTC P2P (Cloudflare/Google STUN, no TURN). If a pair fails to connect within 10s or enters `failed` (4G/CGNAT/UDP blocked), peers fall back to WebSocket binary relay: 16kHz μ-law 40ms frames sent only while speaking (`vr-cap`/`vr-play` AudioWorklets), looped through a local `RTCPeerConnection` pair for Chrome AEC. Dashed voice chip = relayed. Uses `usedtx=1` Opus DTX, `receiver.getSynchronizationSources()` for speaking detection, and 10Hz `transform` updates for 🔊 bubbles (no `requestAnimationFrame` loop; perpetual animations must only animate `transform`/`opacity` to save mobile battery). Testing: Chromium/Edge with `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream`.
- **Exploding Kittens (`games/meono`)**: shared `cards.js`; rules + bot in `server.js`. `state.ask` = deciding seat (differs from `turn` on Favor). `resolve` enforces `now >= react.until`.
- **Incan Gold (`games/incagold`)**: shared `data.js`; `view` hides deck, tent gems, and other choices (unless Vulture Eye charm active). Client animates a local `V` snapshot per event before syncing real state.
- **Flip 7 (`games/flip7`)**: shared `cards.js`; drawn action cards queue in `state.pend`; `view` exposes `ask` and `unseen` counts; Fog masks opponent number cards as `{k:'h'}` until `bust`/`roundEnd`.
- **UNO (`games/uno`)**: shared `cards.js`; playing a card is one atomic `{type:'play', id, color?, to?, give?, uno?}`. `st.stack` holds pending +2/+4 penalties when stackable. Missing UNO shout enters `phase 'catch'` (`CATCH_MS`). Bot jump-ins (`st.jb`) and catches (`catchW.bot`) are precomputed at the end of every `act` and surfaced via `turn().auto`.
- **Codenames (`games/codenames`)**: 5-seat team blocks (`BLOCK` in `data.js`: 0–4 Red, 5–9 Blue, 10–14 Green); lowest occupied seat in a block is Spymaster. `words.js` provides associative clusters for `clueTags`; `server-bot.js` handles Spymaster & Guesser bots. `clue` → `guess` (majority of non-abstain votes flips; ties enter `split` then `settle`). `view` hides unrevealed colors/specials/Fog words/opponent marks.
- **Draw & Guess (`games/vedoan`)**: shared `data.js` (`applyOps`, `judge`/`leaks`), `server-words.js`, `sketch.js` (bot contour drawing from emojis). Real-time `tickRate: 10`; strokes stream via `quiet` `{type:'ink', ops}` (~70ms) and periodic keyframes `st.kf` every 4s. Solved guessers share private `sec` chat via `chatTo`.
- **Ludo (`games/cocangua`)**: shared `rules.js`; dynamic polygon board (`LAYOUT` for 2–6 players); fast home-entry rule by default.
- **Monopoly (`games/typhu`)**: shared `data.js` (40-cell board, `boardOf(chaos)`). `auction` uses simultaneous `{ seats, key }`; `raise()` auto-sells houses then properties on cash shortfall; bankruptcy or `endAt` ends the match.
- **Skull (`games/skull`)**: shared `data.js`; discs `{id, k, o}` track owner `o` across Tornado stack rotations. `place0` simultaneous, then `place → bid → flip → discard?`. Ghosts act asynchronously via `haunt`.
- **Splendor (`games/splendor`)**: shared `data.js` (`buildCards`, `priceOf`, `nobleOk`); post-action prompts flow through `settle()` → `asks` (`steal/snatch/gift`) → `discard` (to 10) → `noble` → `endTurn`. Chaos mode gives later players `min(k, 3)` starting gems to balance first-player advantage.
- **Impostor (`games/maodanh`)**: shared `maps.js` (5 maps, LOS/ray/A*), `data.js`, `rules.js` (`moveMods`), `minigames.js` (client). Client predicts movement and sends `quiet` `{type:'mv', x, y, w}` (~15Hz); server validates speed token bucket (`p.bud`) and collisions. `view` filters entities by `canSee` and computes proximity `hear` volumes. Debug hook: `localStorage.mdn_debug = 1` exposes `window.__mdn`.
- **Coup (`games/coup`)**: shared `data.js` (`SLOTS`, `BLOCKS`, events, black market, ghosts, factions). Actions push steps onto `st.q` (`win`, `resolve`, `lose`, `poison`, `exchange`, `show`, `force`, `end`); `run()` advances automatically until a decision (`st.phase`). Reaction windows pass `key` to prevent stale clicks. `pl.know[id]` tracks peeked cards and forgets on `redraw`.
